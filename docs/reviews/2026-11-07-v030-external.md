## 1. What v0.3.0 changes and why

Until v0.2.3, aranicy's bias engine got per-task statistics by speaking the
`scx_stats` protocol to `scx_lavd`/`scx_mavd`. Every other `sched_ext`
scheduler — and plain EEVDF — degraded to "no per-task stats", which disabled
the project's distinguishing feature on most schedulers.

v0.3.0 ships a **standalone collector** (`aranicy-collectord`) that derives the
same signal set from generic kernel tracepoints, so bias learning is
scheduler-independent. Consequences:

- `collector/` is its own Cargo workspace, **GPL-2.0-only** (it links
  `libbpf-rs` statically and its BPF object is GPL), depending only on the two
  new **MIT** crates (`aranicy-procname`, `aranicy-wire`). aranicy stays MIT.
- aranicy no longer loads BPF, no longer needs `CAP_BPF`/`CAP_PERFMON`, and no
  longer discovers scheduler stats targets: it is a client of the collector.
- Exec events (previously `crates/aranicy-events`) moved into the collector, so
  the collector owns *all* BPF. `crates/aranicy-events/**` and root
  `bpf/exec*.{c,h}` are deleted.
- systemd wiring: `aranicy.service` has `Requires=`/`After=`
  `aranicy-collector.service`; the daemon waits `collector_wait_ms` for the
  socket and then **fails loudly** rather than running without an event source.

## 3. Signal contract (what the numbers must mean)

Every row served on the `sched_samples` target has 8 fields, matching the
names the bias engine already binds:

| Field | Unit | Definition |
|---|---|---|
| `pid` | — | task pid (per-thread) |
| `comm` | — | kernel comm (16 bytes, NUL trimmed) |
| `static_prio` | nice + 20 | **live** value, refreshed on every switch/tick |
| `wait_freq` | events/s | sleeps (`sched_switch` with `prev_state != RUNNING`) over the drain window, EWMA(τ=30 s) |
| `wake_freq` | events/s | wakes **issued by** this task (`sched_waking`, waker context), EWMA(τ=30 s) |
| `avg_runtime_wall` | ns | mean runtime per schedule |
| `task_util_est` | 0..1024 | DEMAND: (running + runnable) duty over the window |
| `cpu_util_wall` | 0..1024 | DELIVERED: running duty over the window |

Deliberate deviations from lavd, all documented in `docs/COMPATIBILITY.md`:

- lavd reports demand 0..1024 and delivered 0..100 (percent) and compares them
  raw; both are normalized to 0..1024 here.
- PELT (`se.avg.*`) is unused: it is a FAIR-class path and reads 0 under
  `sched_ext` (measured on the dev host).
- `wait_freq == 0` **and** `wake_freq == 0` are *meaningful zeros* (a compiler
  neither sleeps nor wakes anyone — it forks), so `sample_score` gates only on
  `avg_runtime_wall > 0`. Earlier revisions treated them as "no evidence" and
  went blind to exactly the workloads bias exists for.

## 4. Known trade-offs / constraints the reviewer must accept as given

- The collector is a **separate package**, not a fork: forking would inherit
  `CAP_BPF`, create two supervisors, and this host runs services under systemd
  only. Socket activation was rejected because `scx_stats` binds its own path.
- `scx_stats` (GPL-2.0-only) is linked **only** into `collector/`; MIT crates
  must not depend on it. Root `Cargo.lock` must contain neither `scx_stats*
  nor `libbpf*`.
- The bias control law is out of scope for this release (grace/fairness/freeze
  semantics unchanged).
- `scx_lavd` on the dev host is owner-managed and must not be touched; the
  collector was validated under `lavd` and the cross-scheduler run is the
  owner's to perform.
- Collector packaging (makepkg split) is **deferred**: `makepkg` fails to link
  the vendored libbpf (`undefined symbol: bpf_map__*`) while `cargo build
  --release` succeeds. Do not re-litigate packaging in this review.

## 5. Internal review round: findings already fixed (do not re-report)

An internal review pass produced 10 findings; all were addressed in this same
working tree. Verified dispositions:

1. **EventClient deadlock** — `next_event` held the stream mutex across the
   blocking `read_exact`, while `wake()` needed the same mutex. Fixed by storing
   `Arc<UnixStream>`, cloning it out, and dropping the guard before reading.
   Live: daemon stop went from "SIGKILL after TimeoutStopSec" to 31 ms; a unit
   test now asserts `wake()` unblocks a pending read.
2. **Runtime source** — `sched_stat_runtime` is emitted from the FAIR class
   upstream, so a kernel that does not route it through `sched_ext` yields no
   ticks. Kept the tracepoint as the primary source but added a `sched_switch`
   residual (`last_tick` / `last_run_start`), which is exact whether or not
   ticks fire. Measured on the dev host (kernel 7.4.0-rc1): rt ≈ 498 ms per
   schedule for a CPU burner.
3. **Stale `static_prio`** — previously written only at entry creation/exec, so
   the closed-loop check froze every entry after its first apply (measured:
   76/400 entries frozen). Now refreshed on every switch and tick; the live
   frozen count fell to 13/407 and `verify_applied` un-freezes entries again.
4. **Collector shutdown** — signals are blocked before any thread spawns; the
   event listener is non-blocking and polled so `stop` is honoured; the pump has
   a write timeout so a stalled client cannot wedge it. Live: `systemctl stop`
   now completes in 276 ms (previously "stop-sigterm timed out, killing").
5. **`sched_process_exit` delete** — it fires from `do_exit()` *before* the final
   `sched_switch`, so it discarded the last window and let the switch recreate a
   zeroed entry (phantom row). The delete is gone; LRU eviction bounds the table
   and userspace detects pid reuse by comm.
6. **Wake attribution** — `wakes_issued` now comes from `sched_waking` (waker's
   context) instead of `sched_wakeup` (target CPU).
7. **Wire name truncation** — the frame now carries the full 256-byte
   `NAME_CAP` with a `u16` length (280-byte frame) instead of truncating to 64
   bytes, which could cut a UTF-8 sequence and make the daemon drop the event.
8. **`wake_freq` gate** — dropped; see §3.
9. **EWMA decay for idle tasks** — rates now decay for every task still present
   in the map, not only those that moved (a task idle for minutes must not
   report its pre-idle rate). Unit test: `idle_windows_decay_the_rates`.
10. **Socket hygiene** — stale event socket removed before `bind`; socket mode
    0600 and `RuntimeDirectoryMode=0700`, so a local user cannot connect first
    and starve the daemon.

## 6. What to review

Please look for **high-confidence defects**, ranked, in these areas:

1. **BPF accounting correctness.** Map type/size, key lifetime, LRU behaviour,
   lost updates, counter saturation, `last_tick`/`last_run_start` overlap (is
   there any path that double-counts or loses runtime?), `prev_state` handling,
   runnable-time bookkeeping, unaligned/unsafe reads, verifier edge cases on
   older kernels (tp_btf availability, `sched_waking` naming).
2. **Window math.** EWMA seeding/decay, unit conversions, division by zero,
   integer overflow in the `u128` paths, clamping, window boundaries, what a
   task that appears/disappears mid-window reports.
3. **Protocols.** `scx_stats` request/response binding (meta shapes, `nr_samples`
   as a string, reply envelope), exec-frame framing (partial reads, EOF,
   oversized frames, u16 length), reconnect/backoff, shutdown, fd leaks.
4. **Daemon lifecycle.** Behaviour with a missing/restarting collector, config
   validation for the new keys (`bias_collector_socket`,
   `collector_events_socket`, `collector_wait_ms`, `bias_starved_min_demand`,
   `bias_starved_ratio`), whether a hung collector can block SIGTERM, lock
   ordering, `RwLock<Arc<RuleSet>>` swap hazards.
5. **`bias.rs` semantics** for the two changed gates and whether the updated
   tests actually assert the intended behaviour.
6. **Licensing boundary.** No GPL dependency reachable from the MIT crates; the
   nested workspace does not leak into the root lockfile; SPDX headers.
7. **systemd units.** Capability sets (aranicy must not need BPF caps), ordering,
   restart semantics, socket paths vs config defaults, `RuntimeDirectory`
   ownership/mode.

## 7. How to build and test

```bash
# MIT workspace (must be green + clippy-clean)
cargo test --workspace
cargo clippy --workspace --all-targets

# GPL collector workspace (separate lockfile; compiles BPF via clang + libbpf)
cd collector && cargo test && cargo clippy --all-targets
```

Runtime observation (host has both units installed):

```bash
systemctl status aranicy aranicy-collector
journalctl -u aranicy -n 50            # "stats sampler live ... (8 fields)"
aranicy dump bias | jq '.state.entries[] | select(.frozen)'
sudo /usr/bin/aranicy-collectord probe --interval-ms 1000 --iterations 3 --rows 10
```

`probe` attaches, prints rows, and exits; it is the fastest way to see the raw
signal without disturbing the services.
